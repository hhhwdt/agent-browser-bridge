## 1. 它实际能做什么

装好之后，**任何能访问本机 `127.0.0.1:18777` 并能读取 token 文件的程序**都可以让浏览器：

- 读取你已登录页面的正文、链接、框架结构，并截图
- 在页面上点击、输入、按键、导航
- 在页面里执行任意 JavaScript
- 读取 Cookie（含 httpOnly）与 localStorage / sessionStorage
- 把文件下载到你的下载目录，把本地文件塞进页面的上传控件
- 关闭标签页

这些动作都以**你本人的登录态**发出。站点侧看到的是"你自己在操作"。

它不切换标签页、不抢焦点、不移动鼠标。反过来说：**你没在看着的时候，它照样在动。**
页面右下角会显示浮动提示、扩展图标会亮标记、标签标题会加前缀，但这些都是通知，不是阻止。

## 2. 你必须自己判断的事

工具只负责执行，不判断该不该执行。下面这些判断没有技术手段能替你做：

1. **指令从哪来。** 你让 agent 做的事情，agent 转述成什么、有没有自作主张，工具看不出来。执行前先看清楚它打算点哪个按钮、提交哪个表单。
2. **不可逆动作。** 提交、发布、发送、删除、付款、审批，一旦发出去就收不回来。工具的风险分级（破坏性文案的按钮需要显式 `--force`）只是防误触，不是安全边界。
3. **站点的规则。** 很多站点在服务条款里禁止自动化访问，企业内部系统还有数据合规要求。用不用、能不能用，由你判断并承担后果。
4. **授权范围。** 站点授权是逐站点给的。一旦授予"所有网站"，它就等于把整台浏览器的读取权交了出去；`cookies` 权限一旦授予，它对**任意**已打开标签页都生效，不是只对当前授权的站点生效。
5. **机器上还有谁。** 桥接服务要求共享 token，扩展从 `chrome.storage.local` 读取（在弹窗里粘贴一次）。其他扩展无法读取 token 文件，无法驱动桥接。但同用户进程能从磁盘读取 token 文件。多人共用或已被入侵的机器上不要用。

## 3. 它不是什么

- 不是绕过登录、验证码、DRM 或风控的工具。它复用你已有的登录态，不做破解；受 DRM 保护的内容不在支持范围内。
- 不是隐藏自身存在的工具。页面上会有可见标记。
- 不是给你在**别人的**机器或**别人的**账号上偷偷使用的工具。在未授权的情况下操控他人浏览器、读取他人数据，属于滥用，与本项目无关，后果自负。

## 5. 降低风险的做法

- 按站点授权，用完即撤（扩展弹窗里有"撤销全部"）。
- 不常用时不要授予 `cookies` 权限。
- 只在需要时开着桥接服务，用完停掉。
- 端口已经只绑定回环地址，不要改成对外监听。
- 让 agent 操作共享文档、生产系统、有真实用户在场的系统之前，先向在场的人确认。
